## Key discoveries

### BIOS requirement
- `firmware.cpp`: `IsRequired()` returns false **only** for FONT20, SERIAL,
  EXTENSION. So **`FMT_FNT.ROM` is required** — the task's 4-file list
  (`FMT_SYS/DOS/DIC/F20`) would have failed boot. Always ship all 7:
  `FMT_SYS, FMT_DOS, FMT_FNT, FMT_DIC, FMT_F20, MYTOWNS, MAR_EX0-3`.
- All 10 ROMs from `Abdess/retrobios` (`main`, `bios/Fujitsu/FM Towns/`) are
  sha256-identical to the known-good `test_assets/bios/` set. FNT=256K, SYS=256K,
  DOS/DIC/F20/MAR_EX0-3=512K, MYTOWNS=32B.

### Media must be split (GitHub 100 MB hard limit)
- Archive.org `fmtownscdcollection` → `FM-Towns CD/Afterburner (1987)(Sega)(Jp-En).zip`
  (204,771,822 B) holds ONE 230,554,800-byte BIN + CUE. Over GitHub's 100 MB
  hard limit → cannot be committed as one file.
- CUE: `TRACK 01 MODE1/2352` INDEX 01 00:00:00; TRACK 02 AUDIO `PREGAP 00:02:00`
  INDEX 01 00:40:30; tracks 03–08 AUDIO at 02:11:34, 05:36:23, 11:09:04,
  13:03:03, 18:00:69, 21:20:38.
- **Split into per-track BINs** (sector 2352 B; track byte range =
  [index01_lba*2352, next_index01_lba*2352)). Largest track 58.7 MB — under the
  limit. Emit a **multi-`FILE` CUE** with `INDEX 01 00:00:00` per track and keep
  the original `PREGAP` line. The CUE reader (`cdrom_cuebin_image.cpp`
  `ParseCueFile`) supports multiple FILE blocks.
- **Correctness check**: the reader adds pregap via `total_pregap_length`, so
  Track 2 resolves to LBA 3180 = 3030 + 150 — identical to the original
  single-file image. Log line: `Track 2 (AUDIO): Start LBA: 3180`.
- `cdrom_media.cpp`: a plain `/media/...cue` path uses
  `GT_CdRomCueBinDefaultLoadOptions()` (`track_files_start_at_index1=false`);
  only `cdrom://` URIs use streaming options. So the split offsets above are what
  matters for our non-URI path.

### Auto-boot shell design (web/index.html + deployed index.html)
- Manifest-driven: shell fetches `assets/manifest.json`
  (`{title, cue, totalBytes, bios:[{name,url,size}], media:[{name,url,size,label}]}`),
  streams each asset into `/bios` or `/media` via `fetchToFS` (streamed reader
  for a smooth bar), then `asuka_web_init(bios, media=/media/<cue>)` +
  `asuka_web_start`.
- **No manifest → graceful manual mode**: reveal the drop-zone overlay so the
  old drag & drop flow still works. This keeps the shell usable standalone.
- `mountFiles()` was made non-destructive: it only clears `/bios` or `/media`
  when the user actually supplied files for that bucket, so a manual Boot cannot
  wipe the auto-loaded assets.
- Loader: arcade marquee + progress bar in `.stage`; waits up to 6 s for
  `crossOriginIsolated` (the coi service worker reloads the page once on a
  first header-less visit). Touchpad is shown automatically after boot.
- Manifest is the only place asset filenames live → the tracked Asuka source
  shell stays free of copyrighted filenames and boots the generic flow.
- `_headers` now caches `/assets/*` for a year (immutable) and revalidates
  `/assets/manifest.json`.

### Build is deterministic
- `bash scripts/build_web.sh` (emcc 7.0.0, `source /tmp/emsdk/emsdk_env.sh`)
  reproduced **byte-identical** `asuka_web.wasm` (sha256 `d4569a57…`) and

# Session 2 — Fix controls + strip UI to a minimalist canvas (deploy `846dfe7`)

## Why controls never registered (root cause)
The deployed shell's `KEY` map used **capitalised** names
(`{Up:1, Down:2, Start:5, A:7, …}`), but both the touchpad markup
(`data-key="up"`, `data-key="a"`) and `SCAN_TO_KEY` used **lowercase**
(`"up"`, `"a"`). `sendKey()` did `KEY[name]` → `undefined` → `return` **before
calling anything**. So neither the touchpad nor the keyboard ever reached the
engine — a silent no-op, not a broken export. Fix: lowercase `KEY` keys so they
line up 1:1 with `data-key` / `SCAN_TO_KEY`, and normalise with
`String(name).toLowerCase()` in the send funnel.

## Other input facts
- The exported C entry point is **`asuka_web_key(key, pressed)`** — there is no
  `asuka_web_send_input`. (The task named a function that does not exist; the
  real export is in `src/web/main_web.cpp`.)
- The engine keyboard sink is **idempotent**: `Keyboard::KeyPressed` returns
  early when `m_state.keys[key]` is already true (same for release). So a
  redundant JS path + SDL2's own listener cannot double-fire.
- Kept the window-level keydown/keyup listeners (not just the canvas) because
  Emscripten SDL2 registers its key listener on **`window`**; the canvas focus
  is belt-and-braces and satisfies the "auto-focus canvas" requirement.
- Touch pad buttons: `pointerdown` → `sendInput(name,true)`, `pointerup` /
  `pointercancel` / `lostpointercapture` → release; `e.preventDefault()` +
  `touch-action:none` + `setPointerCapture`. A `pressed` Set tracks held keys
  and `releaseAll()` runs on `blur` / `visibilitychange` so nothing sticks.
- Added **`asuka_web_input_events()`** to `src/web/main_web.cpp` (counts every
  `asuka_web_key` call, reset on init) purely as a diagnostics/test hook — it
  is how the headless test proves input reaches the engine.

## Game Port 1 (Towns Pad) input fix — 2026-11-13 (Task 6)
Symptom: web controls reached the engine, but FM Towns arcade games (After
Burner) ignored them on the title screen. Root cause: `FMTownsEngine::send_input`
only fed the FM Towns **keyboard**; arcade titles poll **Game Port 1** (Towns
Pad) instead, so the pad stayed all-released (0x3F) and nothing responded.

Geartowns input API (all in `src/input/`):
- Game Port 1 = I/O port `0x04D0` -> `Input` index 0 (`GT_CONTROLLER_1`);
  port `0x04D2` -> index 1. `system/io.cpp` routes both to `m_input->Read()`.
- Pad state is a **level**, not an edge: `Input::SetGamePadState(port, state)`
  with `GT_GamePad_State{ u16 buttons }` (input_inline.h:33). Also
  `SetInjectedGamePadState` (OR-ed in, for automation).
- `Input::ReadGamePad` maps `GT_GAMEPAD_*` flags to the 6 status lines; port 1
  defaults to `GT_CONTROLLER_ORIGINAL_GAMEPAD`, so UP/DOWN/LEFT/RIGHT/RUN/
  SELECT/A/B all work. `0x3F` = nothing pressed.
- `GeartownsCore::GetInput()` returns the `Input*`.

Fix: `send_input()` now mirrors each key to the pad as well as the keyboard and
keeps a latched `gamepad_buttons_` mask (clear on reset/shutdown). Key->pad:
Up/Down/Left/Right -> dirs, Start -> RUN, Select -> SELECT, A/B -> A/B,
X/Y -> X/Y, L/R -> Z/C.

Proof it matters (4000 frames, After Burner):
- Pad routing ON  -> pressing Start/A near the end changed **23,614 px (31%)**;
  instrumented vendor showed `gameport1 val=0x33` (RUN held) read by the game.
- Pad routing OFF -> frames byte-identical (`md5 471c8873…`); input dead.
- `scripts/verify_fmtowns_boot.sh` now boots twice (idle vs Start/A) and FAILS
  if the final frames match. Full run: 733 colours, 72% ink, **48% px changed**
  with input -> PASS.

Also verified the game only polls **port 1** (port 2 never read in 2500 frames),
and the earlier "no effect" A/B was just a press landing during POST (frame
1300); After Burner's title screen is reached well after that.

Vendor was instrumented for the trace and reverted (`git status` clean).

## Task 8: PC-98 engine (WebNP2 / NP2kai) — design findings

### Which NP2kai form to embed
- NP2kai has FOUR front-ends in-tree. The **libretro** config
  (`sdl/libretro/libretro.c`, compiled with `-D__LIBRETRO__`) is the only one
  that is **headless and pull-model**: `retro_run()` → `pccore_exec(true)` one
  frame, then `video_cb(FrameBuffer,w,h,pitch)` + `audio_batch_cb(...)`. That
  maps 1:1 onto `IEngineCore` (host owns the loop, pulls fb+audio). The SDL2
  front-end (`sdl/em/main.c`) is an ASYNCIFY main loop — wrong shape.
- `sdl/webnp2api.c` (WebNP2's own API) is NOT used; it wraps the SDL2 build.
  But its key path is the same one we use: `webnp2_key(code,down)` ==
  `keystat_senddata((code&0x7f)|(down?0:0x80))` with **PC-98 make codes**.

### Core layout / build facts (probed)
- 619 sources (600 C + 19 CXX) per `sdl/Makefile.common`. All compile under
  `emcc`/`em++` with the libretro defines. Two gotchas:
  - `-DSUPPORT_PNG` must be **omitted** (pulls `png.h` into `vram/scrnsave.c`;
    NP2kai's CMake adds it only because it links libpng).
  - C++ TUs need `-include compiler.h` (upstream does this); otherwise
    `sound/mamebsd/ymfm_opq.cpp` misses `<cmath>` for `std::abs`.
- `sdl/libretro/compiler.h` is the libretro compiler header (pulls
  `features/features_cpu.h`, `sdlremap/sdl.h`, `retro_inline`), **not**
  `sdl/em/compiler.h`. `GETTICK()` = `cpu_features_get_time_usec()/1000`.
- libretro-common: only `file_stream.c` (+ its deps) is needed from
  `sdl/libretro/libretro-common/`; the rest is header-only for our use.
  Include dirs must add `.../include/{streams,file,vfs,lists,string,...}`.
- Build generator: **make** (ninja absent).

### Frontend contract (what PC98Engine must do)
- `retro_set_environment` / `retro_set_video_refresh` /
  `retro_set_audio_sample_batch` / `retro_set_input_poll` /
  `retro_set_input_state` must be called before `retro_init()`.
  - Our `environ_cb` must answer `GET_SYSTEM_DIRECTORY` (BIOS dir),
    `GET_VARIABLE` (return false → defaults), `SET_PIXEL_FORMAT` (accept
    XRGB8888; must set `np2cfg.usegd5430=1` **before** `retro_init` so
    `draw32bit=1` and `scrnmng.bpp=32`).
  - `video_cb` gives us `FrameBuffer` (global, `LR_SCREENWIDTH*LR_SCREENHEIGHT`
    = 1640*1024 uint32) with pitch `w*4`; `scrnmng_getsize` = 640x400 default.
  - `audio_batch_cb(buf, frames)` → interleaved s16 stereo, 44100 Hz.
- `retro_load_game({path})` sets `RPATH`; the **first** `retro_run()` calls
  `pre_main(RPATH)` → `np2_main()` which does `initload()`, `pccore_init()`,
  `pccore_reset()`, mounts FDD/CD from `np2_main_disk_images_paths[]`, then
  returns. So: call `retro_load_game` with the media path, then step one
  "warm-up" frame. Subsequent `retro_run()`s each emulate one frame.
- `retro_serialize`/`retro_unserialize` go through `statsave_save_d/load_d`
  (file-based temp `.sxx`). `retro_serialize_size` needs a save first.
- `retro_deinit()` → `np2_end()`.
- Key injection: `keystat_senddata(code)` where code is a PC-98 make code
  (0x00-0x74 range) — same table as `keystat.h` NKEY_* / WebNP2 keymap.ts.
  Down = code, Up = code|0x80.
- `np2_main_disk_images_paths[50][MAX_PATH]` + `np2_main_disk_images_count`
  are the FDD mount table (extern in `sdl/np2.c`). `diskdrv_setfdd(drive,path,0)`
  is the direct mount call used by WebNP2 (`webnp2_set_fdd`).

# Project memory (Asuka)

Repo: `M5Devs/Asuka` — "Retro Vintage PC Runner & Modular Environment".
Cross-platform, modular vintage PC runner. **C++17** + CMake ≥ 3.16, GPLv3.
Build: `cmake -B build && cmake --build build` (default type Release).

## Architecture (verified)
- Plugin model is **Libretro-inspired but object-oriented**: the *host owns the
  main loop* and *pulls* state (`get_framebuffer`, `get_audio_samples`) after
  `step_frame()`. Cores never drive the loop. Two hosts: headless
  `asuka_runner` (`src/main.cpp`) and interactive `asuka_play`
  (`src/interactive/main_sdl.cpp`).
- `include/asuka/IEngineCore.hpp` — pure-virtual ABI. Framebuffer **XRGB8888**
  (`uint32_t`); audio **interleaved stereo `int16_t`**, `sample_count` is *per
  channel*. Factory symbols resolved by name: `create_engine`, `destroy_engine`
  (typedefs `CreateEngineFunc`/`DestroyEngineFunc` at *global* scope).
- `include/asuka/Input.hpp` — host-level `asuka::Key` enum (d-pad, Start,
  Select, A/B/X/Y/L/R). `send_input` takes a `uint32_t`; the *host* translates
  physical input to `asuka::Key` and *each core* maps those to its own codes
  (Libretro `RETRO_DEVICE_ID_JOYPAD_*` analogue). Cores ignore unknown keys.
- `PluginLoader` wraps `dlopen/dlsym/dlclose` (POSIX) and
  `LoadLibrary/GetProcAddress/FreeLibrary` (Win32), gated on
  `ASUKA_PLATFORM_WINDOWS` (`include/asuka/Export.hpp`). `EngineInstance` is the
  RAII owner: **`engine.reset()` calls `shutdown()` then `destroy_engine()`**,
  and must happen **before `loader.unload()`**.
- Outputs: `build/bin/asuka_runner`, `build/bin/asuka_play` (SDL2, optional);
  dummy plugin `build/plugins/dummy/libasuka_dummy_engine.so` (runner's default
  lookup, overridable via `ASUKA_PLUGIN_PATH` / argv[1]).

## FM Towns plugin (Geartowns, `plugins/fmtowns`)
- Only the emulation core + data deps are built; the SDL3/OpenGL/imgui/glad
  desktop shell is excluded, so the plugin has **no GUI deps**. Submodule
  `vendor/Geartowns`. Uses `GT_DISABLE_DYNAREC` (interpreter, deterministic).
- `GT_MAX_FRAME_BUFFER_WIDTH/HEIGHT` = 1024×768 (our framebuffer alloc).
  Audio: Geartowns accumulates one frame into a buffer capped at
  **`GT_AUDIO_BUFFER_SIZE` (8192)** and copies the whole `m_buffer_index` out,
  so size our destination to `GT_AUDIO_BUFFER_SIZE` — a per-frame estimate
  overflows (was a heap-corruption bug).
- **Input mapping (`ToGtKey`)**: d-pad→cursor keys, Start→`GT_KEY_RETURN`,
  Select/A→`GT_KEY_SPACE`, B/L→`Z`, X/R→`X`, Y→`C`. Verified end-to-end by

### Minimalist shell + input fix (deploy `846dfe7`, 2026-11-13)

  names (`Up`,`A`) while the touchpad `data-key` and `SCAN_TO_KEY` used

  everywhere and normalise in one send funnel.

  repeat), so redundant JS + SDL2 paths are safe. Emscripten SDL2 listens on

  `Input::ReadGamePad` maps `GT_GAMEPAD_*` to the 6 status lines; `0x3F` = idle.
  Port 1 defaults to `GT_CONTROLLER_ORIGINAL_GAMEPAD` (all buttons work).

## Web ROM loader / machine switch — Task 9 (commit `8d65271`)
