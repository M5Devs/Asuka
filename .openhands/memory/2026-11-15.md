# 2026-11-15 — X68000 (PX68k) input registration fix

## Task
"Fix X68000 input": three claims to verify — (1) missing
`retro_set_controller_port_device`, (2) PX68k defaults to `PAD_NONE` so joypad
reads are dead, (3) host A/B mapping wrong. Then verify with a real title and
ship the web bundle.

## Ground truth (all three claims checked against the vendored core)
1. **Already present.** `X68kEngine.cpp:224` calls
   `retro_set_controller_port_device(0, RETRO_DEVICE_JOYPAD)`, and PX68k does
   implement it (`vendor/PX68k/libretro.c:1687` → sets `PAD_2BUTTON`).
2. **False.** `Config` is a zero-init global (`libretro/prop.c:42`), and
   `joystick.h` has `PAD_2BUTTON == 0` (`PAD_NONE == 6`). So the default pad
   type is already 2-button — joystick reads are not zeroed.
3. **Real bug.** PX68k's `PAD_2BUTTON` branch (`libretro/joystick.c:844`)
   maps `RETRO_DEVICE_ID_JOYPAD_A → JOY_TRG2` and `..._B → JOY_TRG1`. The host
   had `Key::A → JOYPAD_A`, i.e. primary fire landed on the *secondary* trigger.
   Fixed by making `Key::A → JOYPAD_B` (TRG1) and `Key::B → JOYPAD_A` (TRG2).

## Change (`plugins/x68k/X68kEngine.cpp`)
- `ToJoypadId`: A/B un-swapped as above (named consts
  `kRetroPadPrimaryFire`/`kRetroPadSecondaryFire`).
- `input_state_cb` `RETRO_DEVICE_KEYBOARD` branch: dual-dispatch — the pad
  START/FIRE bits also answer for `RETROK_RETURN` / `RETROK_SPACE`. Needed
  because PX68k's 2-button pad exposes no start/select, while X68000 titles
  (Cho Ren Sha, etc.) read start/fire from the keyboard.

## Verification (headless, `build/bin/asuka_runner`)
- Game: **Cho Ren Sha 68K v1.01** (Famibe No Yosshin, 1995) `.dim`, 1,261,824 B,
  from archive.org item `ch68_101_x68k` (`Disks/Chourensha 68K v1.01 ...zip`).
  It is a plain 2HD floppy; PX68k boots it, and the machine spends a long time
  in Human68K DOS text mode before the game's own screen.
- **Instrumented probe** (temporary counters in `input_state_cb`, since
  removed): PX68k polls the joypad *every frame* — `joy_q=11900` over 700
  frames, all 16 ids (`joy_ids=0xffff`). Pressing `a` → `kbd_spc=4`; pressing
  `start` → `kbd_ret=4`. Proves both the pad read and the dual-dispatch fire.
- **Frame divergence** (baseline vs `--press`): pressing `a` or `start` changes
  emulated output; pressing `up` does not (nothing to move yet). A longer
  1400-frame run with several presses diverged on 32 frames. Keyboard path
  (`--press-scancode 700:97`) also diverged (37 frames) — both routes reach
  the guest.
- `ctest` 3/3 pass. Clean rebuild, zero warnings, vendor tree pristine.
- Web bundle built with Emscripten (`/tmp/emsdk`, emcc 7.0.0) →
  `web/dist/{asuka_web.js,asuka_web.wasm,index.html,_headers}`.

## Runner gotchas learned
- The scancode flag is `--press-scancode <frame>:<code>` (not `--scancode`).
- `--press` holds for 4 frames then releases.
- `build_web.sh` has **no `--release`** flag (it is Release by default); usage
  is `[--jobs N] [--out DIR]`.
- emsdk needs `EMSDK_PYTHON=/usr/local/bin/python3` (the `/usr/bin/python3`
  path in this image does not exist; the container's python is
  `/usr/local/bin/python3.13`).

## Screen-reading notes (X68000 text mode)
- PX68k renders X68000 text as **black + one off-white (231,227,231)**; the
  768x512 frame is RGB with an 8x16 glyph cell grid.
- The ANK (ASCII) font lives in `cgrom.dat`; a reliable landmark is the `H`
  glyph at file offset `0x13266`, which puts `'A'` (0x41) at `0x131F6`, so
  glyph `n` = `0x131F6 + (n-0x41)*16`, 16 bytes MSB-first, 8 px wide.
- Easy way to prove *any* input reached the machine without OCR: md5 every
  dumped PPM and diff a `--press` run against a no-input baseline.
